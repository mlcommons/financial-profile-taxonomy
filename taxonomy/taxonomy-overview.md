# Agent Reliability Profile Taxonomy v0.1.0: Overview

## Introduction

AI agents can take actions. Unlike chatbots, agents invoke tools (API calls, file writes, code commits) that change state in the world, and at times those actions go beyond what is intended. **Agent reliability** is assurance that an agent will operate within intended bounds and limits.

Today each deployer defines those bounds idiosyncratically, and institutions, vendors, assessors, and regulators each work with their own vocabulary. This taxonomy fixes that vocabulary for agent deployments in financial services. It does not prescribe what any deployment should look like; it fixes the terms in which a deployment is described, so that the description can be tested and compared.

## The Bounded Claim

For each agentic deployment, the institution should be able to state and support:

> **This agentic system functions reliably within its operating boundary**, i.e., at a defined autonomy tier, within a defined operational design domain, for defined classes of action, under a defined control envelope.

The claim tells a relying party the conditions under which the agent may be trusted and, with equal precision, the conditions under which the claim does not apply.

## The Four Axes

| # | Axis | Value on a Profile | Page |

| 1 | **Autonomy tier (T)**: how much the agent does on its own, and who provides the fallback | One tier (or the status U), plus six modifiers | [Autonomy Tier](axes/autonomy-tier/README.md) |

## Design Principles

1. **Standardization, not invention.** The axes correspond to properties already familiar to deploying institutions. The contribution is a fixed vocabulary.
2. **Borrowed from safety engineering.** In automated driving the safe level of automation depends on operating conditions (SAE J3016). Agents act across a far wider range than conveying passengers between two points, so a single conditioning axis is insufficient; the Profile uses four.
3. **Joint determination.** The axes operate as a single test specification. The autonomy tier dictates the response to failure; the ODD establishes the verifiable operating context; the action sets define possible actions, their consequences, and recovery; the control envelope determines which protections must be observed operating during the test.
4. **Floors before scores.** A failed safety floor blocks issuance even when average task performance is high. Metrics stay disaggregated.
5. **Evidence over assertion.** Unevidenced tier claims are treated as unprofiled. Every Profile field carries provenance.
6. **Change-sensitive validity.** Model updates, new tools, expanded credentials, and weakened controls can void or narrow a Profile.

## Scope

The Profile records **operational reliability** evidence. It complements, without replacing, institutional risk frameworks and other agent governance mechanisms. Fairness, explainability, data governance, consumer compliance, and cybersecurity adequacy remain governed by their own frameworks, though Profile evidence may inform them.

The taxonomy is built for financial services. The four-axis architecture could apply to other domains, but the operational design domain in particular would need to be crafted by domain experts.
