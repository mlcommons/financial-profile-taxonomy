# Axis 3: Action Class (A+ / A-)

## Definition

The type and reversibility of actions the agent may take, from read and draft through submit, transact, and move funds. The action classes an agent can and cannot invoke materially shape its risk profile.

**Value on a Profile:** a pair of sets: a **permitted set A+** and a **prohibited set A-**, both stated explicitly. The prohibited list carries as much of the claim as the permitted list.

## Splitting Rule

The organizing variable is **reversibility**, graded with consequence. Twelve classes are ordered from actions with no side effects (A1) to actions that amplify the agent's own capability surface (A12).

## Distinctive Features

**A pair of sets.** Stating A- explicitly, rather than leaving it as the complement of A+, makes the claim's boundary examinable and lets a relying party see exactly which consequential classes are excluded.

**Maps onto existing systems.** The axis maps directly onto the identity, entitlement, and change-control systems an institution already runs, which makes it examinable through access boundaries, application permissions, workflow configuration, and observed tool calls.

## Multi-Agent Systems

A system composed of multiple subagents can execute **composite actions that no single subagent holds**: one agent retrieves data, another constructs a transaction, a third submits it. The composite Profile records the emergent class and the control points across the chain, and testing addresses the system as a whole.

## Agent-Building Platforms

Tools are resolved per session from a closed registry, and out-of-set action classes must be unavailable in software, not merely prohibited by policy. See [Agent-building platforms](../../cross-axis/agent-building-platforms.md).

## Falsification

An action claim fails if entitlements permit classes outside A+.
