# Axis 2: Operational Design Domain (O)

## Definition

The operational design domain (ODD) is the defined context in which the system is meant to function: **the use case, the data, the operational scope, the customer population, the jurisdiction, and the cost of failure** (e.g., business impacts, regulatory penalties). The concept is borrowed from its use in automotive certification. The ODD specifies the test environment and is the domain-specific part of any assessment.

**Value on a Profile:** an ODD instance: one or more use cases, multiplied by the deployment's customer population, data sensitivity, cost of failure, and jurisdiction.

## An Open Set

Unlike the other three axes, the ODD is an **open set**. Only the ODD *schema* admits standardization; *instances* are built one at a time by the institutions developing agents.

The working group has identified fifty-two candidate use cases in financial services. The list is preliminary and is expected to improve and grow over time; new use cases are the most common expected contribution (see [CONTRIBUTING.md](../../../CONTRIBUTING.md)).

## Splitting Rule

Use cases are grouped by **line of business**. Each use case then multiplies by four factors: customer population, data sensitivity, cost of failure, and jurisdiction.

## Boundary Detection

Use-case boundary detection resides in this axis. The agent must recognize when an observation, request, resource, or state lies outside its assessed domain, and then **halt, refuse, or escalate** as the Profile specifies. For example, a market research agent (`ODD.30`) should refuse instructions to engage in margin-call actions (`ODD.34`).

Boundary detection is a defined test at Level 2 and above, distinct from following an escalation rule the agent was given.

## Multi-Agent Systems

For a multi-agent system, the composite domain is the **union of component domains plus the inter-agent channel**, whose messages, delegated tasks, and credential transfers form part of the evaluated environment.

## Agent-Building Platforms

A platform's ODD is open by construction; each hosted agent states its own bounded domain. See [Agent-building platforms](../../cross-axis/agent-building-platforms.md).

## Falsification

A domain claim fails if the agent proceeds after leaving its domain.
