# Axis 4: Control Envelope (C)

## Definition

The control envelope is the layered containment around the agent: approval gates, least-privilege access, rollback, logging, tested safe state. It is what makes a given autonomy tier acceptable within a given domain.

**Value on a Profile:** a subset of the catalogue. For each control, the Profile records whether it is present, how it is configured, the source of the assertion, and the validation method and result.

## Splitting Rule

Controls are grouped by the **layer** at which they operate. Layers are tested as a whole: controls at different layers catch different failures, and none suffices alone.

## How Envelopes Are Assembled

An envelope is a subset of the catalogue. In practice, controls bundle into a few standard per-layer profiles, assembled by crosswalk to OWASP, NIST, and other frameworks. The catalogue mirrors existing control frameworks.

Documentation alone can support a Level 1 assertion. Higher levels require evidence from inspections, evaluations, or tests. See [Assurance levels](../../assurance-levels.md).

## A Descriptive Axis

On this axis the Profile is **descriptive**: it records the envelope an institution has chosen and tests whether the envelope is real, leaving the choice of envelope to the institution and its regulators. (By contrast, the Monetary Authority of Singapore's SAFR framework takes a more prescriptive approach to runtime controls.)

## Falsification

An envelope claim fails if a named control is documented but absent from the running configuration.

## Open Work

The v0.1.0 catalogue fixes control **labels** (from Appendix B.4 of the preprint) and **IDs** (`<layer>.<slug>`, shared with the Profile Kit).
